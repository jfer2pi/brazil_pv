# Brazil Solar PV Fleet

Shiny dashboard of Brazil's centralised (utility-scale) solar PV fleet and pipeline, built on ANEEL open data. A sibling of the US Solar PV Fleet app: same Linear-style theme, KPI cards, bubble map, capacity trajectory, state and size charts, owner and plant tables. No API keys.

## Data

| Source | File | Used for |
|---|---|---|
| ANEEL SIGA (required, daily) | `siga-empreendimentos-geracao.csv` | Every UFV grant: phase, MW, owners, municipality, coordinates |
| ANEEL RALIE (optional) | `ralie-usina-atual.csv` | Works status, viability, schedule, complex, market (ACR/ACL) |
| ANEEL RALIE units (optional) | `ralie-unidade-geradora-atual.csv` | Expected COD per unit (SFG forecast, else grant act) |

The app downloads all three from dadosabertos.aneel.gov.br and caches the parsed result to `br_solar.rds` for 24 h. If ANEEL can't be reached it keeps the cache, or reads copies of the CSVs saved next to `app.R` under the names above.

**Outside Brazil:** dadosabertos.aneel.gov.br often doesn't answer foreign connections. The app gives up after 15 s and reads the local CSVs instead, so download the files once from a connection that reaches ANEEL (or a Brazilian VPN) and save them next to `app.R`. Only the SIGA file is required. Set `options(br_pv.offline = TRUE)` before `runApp()` to skip the download attempt entirely.

**Stages** follow SIGA's `DscFaseUsina`: Operação → Operating, Construção → Under construction, Construção não iniciada → Not started.

**Capacity** is ANEEL's inspected kW once verified, granted kW before.

**Owners** come from `DscPropriRegimePariticipacao` ("50% para X (PIE); 50% para Y (PIE)"). The owner table shows equity MW (share × plant MW). The map and plant table show the lead owner.

**Coordinates** outside Brazil with an obvious slip (missing minus sign, lat/lon swapped) are corrected; the rest are left off the map but stay in the tables.

## Run locally

```r
install.packages(c("shiny", "bslib", "httr2", "dplyr", "tidyr",
                   "leaflet", "plotly", "DT", "htmltools"))
shiny::runApp()
```

## Deploy on Posit Connect Cloud

Connect Cloud runs outside Brazil and probably can't reach ANEEL either, so the three CSVs are committed next to `app.R` and the app reads them when the download fails. Replace them with fresh copies (same names) to update the data.

`manifest.json` is regenerated by the *Write manifest* GitHub Action on every push that changes `app.R` or a CSV. To write it by hand:

```r
rsconnect::writeManifest(appFiles = c("app.R", list.files(pattern = "^(siga|ralie)-.*\\.csv$")))
```
